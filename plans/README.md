# Implementation Plans

Generated by the `@improve` skill on 2026-06-20 against commit `ea71909`
of `portfolio-webgl/`. The audit reviewed the entire `portfolio-webgl/`
tree (HTML pages, ES modules under `src/`, legacy `javascript/`, the
Webflow-exported `css/style.css`, and the Firebase hosting config) and
produced 30+ findings. After vetting, 5 plans are written below —
the top 5 by leverage, with the rest recorded under
"Findings considered and rejected" so they are not re-audited on the
next cycle.

Execute in the order below unless dependencies say otherwise. Each
executor: read the plan fully before starting, honor its STOP
conditions, and update your row when done.

## Dependency notes

- Plans 001–005 are designed to be **independent**. They can be
  executed in any order, even in parallel by separate executors on
  separate branches.
- Plan 001 (verification baseline) is the **strongly recommended
  first plan**. Every subsequent plan benefits from the `npm run
  lint:html`, `npm run check:js`, and CI gating it adds. If the
  executor chooses to skip plan 001, every other plan's
  `Done criteria` section will reference commands that don't exist
  yet (`npm run lint:html`).
- Plan 003 (audio + form hardening) and plan 004 (WebGL wins) both
  modify `src/main.js` slightly (plan 003 hardens audio paths;
  plan 004 has no direct overlap with `src/main.js`). Merging their
  branches is conflict-free.
- Plan 005 (10-card gallery) modifies `pages/work.html` and
  `css/style.css`. No other plan touches these files.
- Plan 002 (project docs) is content-only and does not conflict
  with any other plan.

## Findings considered and rejected

These findings were raised during the audit, vetted against the
codebase, and rejected with a one-line reason. They are recorded
here so the next cycle's audit does not re-raise them.

### REJ-01: Add 3 missing case-study cards (aipay-landing, aitu-halogens, ciridae)

**Source**: pre-audit recon claim, inherited from `GEMINI.md:106-111`.
**Vetting result**: false positive. `grep -c 'p-col' pages/work.html`
returns 10. All 10 webp files in `assets/work/` are mounted
(`pages/work.html:285, 312, 339, 367, 395, 422, 449, 477, 506, 535`).
The "missing 3 cards" claim was based on stale `GEMINI.md`. Plan 005
makes the 10-card reality intentional; this finding is rejected.

### REJ-02: WebGL sphere missing on the home page

**Source**: pre-audit recon claim, inherited from `GEMINI.md:97`.
**Vetting result**: false positive. `index.html:597` is
`<div style="filter: invert(0%)" class="webglholder"></div>`. The
sphere is mounted; the v2 refactor did not revert it. `GEMINI.md`
is stale. No finding.

### REJ-03: `pages/credits.html` is missing (referenced in git log)

**Source**: pre-audit recon claim, inherited from `GEMINI.md:129-133`.
**Vetting result**: not actionable in the live site. The credits
page is referenced only in `index.backup.html` (which is ignored
by `firebase.json:13`). No live page (`index.html`, `pages/about.html`,
`pages/work.html`, `pages/contact.html`, `pages/cookie.html`) links
to credits. The git-log reference is from before the v2 refactor
removed the live page. No 404 trap exists. No finding.

### REJ-04: Three.js r125 → r150+ migration

**Source**: audit subagent (security + deps), [DEPS-02].
**Vetting result**: deferred. The migration is L effort, H risk
(loader path rename, color management, ES module imports), and
r125 is still functional. Plan 004 reduces the surface by removing
the unused OrbitControls; the full migration is a follow-up cycle
with its own audit and plan.

### REJ-05: Locomotive Scroll v4 → v5 migration

**Source**: audit subagent (security + deps), [DEPS-03].
**Vetting result**: deferred. v5 is a rewrite on Lenis with
breaking API changes. The current blast radius is small (one
bridge file: `src/scroll/LocomotiveBridge.js`). The migration
should be paired with a deliberate scroll refactor, not done
as a standalone version bump. Defer.

### REJ-06: Purge unused CSS from `css/style.css` (9.3K LOC)

**Source**: audit subagent (perf + tech-debt), [TECHDEBT-03].
**Vetting result**: deferred. The CSS is Webflow-generated and
contains many interaction-specific selectors (hover states, IX2
animation hooks) that a PurgeCSS pass would mis-categorize. The
risk of visible regressions is high; the load-time win is
modest (the file is 139KB and not the dominant LCP blocker). A
future plan can do a careful manual pass when the operator
moves away from the Webflow export.

### REJ-07: Collapse `javascript/`, `src/`, and inline-script RAFs into one loop

**Source**: audit subagent (perf + tech-debt), [PERFORMANCE-02] and
[CORRECTNESS-06].
**Vetting result**: real but oversized for this cycle. The active
module-level RAFs (`DesktopHorizontalScrollController.js:69`,
`MobileFix.js:55, 184`, `SmoothVerticalScroll.js:126, 144`) do
exist and do create parallel frame schedulers, but the
"consolidate to `src/core/Loop.js`" change is M–L effort and
risks regressing scroll feel. The legacy inline-script RAF
**is not present in active pages** (only in `index.backup.html`,
which is ignored by deploy). The M-effort plan is deferred; the

## Audit methodology

The audit was a 4-subagent parallel pass, each subagent given a
cluster of categories from
`improve/skills/improve/references/audit-playbook.md`:

1. **Correctness + tests** (HIGH thoroughness per the playbook
   table at "standard" effort).
2. **Security + dependencies + DX** (HIGH thoroughness).
3. **Performance + tech-debt** (MED thoroughness; the Webflow CSS
   and the active-vs-legacy distinction required the most care).
4. **Direction + docs + WebGL supplement** (MED thoroughness; the
   WebGL supplement is not a standard 9-category row but the
   portfolio's signature is a Three.js sphere, so the supplement
   was added).

Each subagent received: the playbook path, the recon facts (HEAD,
no build/test/lint, 8+ CDN scripts without SRI, the dual
animation systems, the 20+ stale `bolt-*` branches, etc.), the
specific category headings to read, and the explicit instruction
to return findings only (no plans, no edits).

The lead (the session you're reading) then re-read each cited
`file:line` in the VET phase and dropped 4 false positives that
came from stale `GEMINI.md` (REJ-01, REJ-02, REJ-03, and the
jQuery-SRI claim — jQuery has SRI, the others don't). The top 5
findings by leverage were written into the plans in this index.

## How to use this index

- **To run a plan**: read the plan file in full, then execute its
  steps in order, running every `Verify` command and confirming
  the expected result before moving on.
- **To skip a plan**: change the Status cell to `REJECTED` with a
  one-line reason. The plan file stays; future agents see why
  the operator declined it.
- **To add a plan**: read the playbook, add a row to this table,
  follow the plan-template, and link the file in the `| Plan |`
  column.
- **To reconcile**: when the operator comes back next session,
  run `/improve reconcile`. It will spot-check DONE plans,
  refresh DRIFTED plans, and retire FIXED-INDEPENDENTLY findings.

## Re-running the cycle

When the operator wants a fresh audit, the simplest loop is:

1. `git pull` to the current HEAD.
2. Mark any DONE plans as VERIFIED (the Done criteria should still
   hold).
3. Mark any BLOCKED plans and investigate (the BLOCKED reason
   is in the table cell).
4. Update the rejected-findings list — anything fixed
   independently is removed.
5. Run a fresh audit. The next audit's findings table will be
   smaller because this cycle's high-leverage work is now
   DONE; lower-leverage items (REJ-04, REJ-05, REJ-08, etc.)
   become the new top of the table.
